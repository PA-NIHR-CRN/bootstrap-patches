Bootstrap 3.4.1 - XSS Vulnerability PoC

SNYK-JS-BOOTSTRAP-7444617

This demonstrates an XSS vulnerability in Bootstrap's button plugin when using data-loading-text.

Test Case: XSS via data-loading-text

Expected Result (Vulnerable): If vulnerable, an alert box should appear when clicking the button, as the XSS payload from the input field is executed.
Patched Result: No alert box should appear; the payload should be sanitized.
Note: This page currently uses the patched version of Bootstrap. To recreate the vulnerability and see the XSS attack in action, update the <head> tag includes to reference the original vulnerable Bootstrap 3.4.1 from a CDN: 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/css/bootstrap.min.css">
<script src="https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/js/bootstrap.min.js"></script>

Patch Details

File Modified: js/button.js

Change Applied: Added an early return in the Button.prototype.setState function to no-op the loading state functionality, which prevents the XSS vulnerability via data-loading-text.

Location: Line 28-30 (beginning of setState function)

Code Change: 
Button.prototype.setState = function (state) {
  // No-op for loading state to prevent XSS vulnerability (SNYK-JS-BOOTSTRAP-7444617)
  if (state == 'loading') return
  
  // ... rest of function continues
Rationale: Since the application does not use data-loading-text functionality anywhere, completely disabling the loading state feature eliminates the vulnerability without impacting functionality.
