Reproduction of Bootstrap Vulnerability:
Cross-site Scripting (XSS) using DOM Clobbering during HTML sanitization

Vulnerability information

CVE: CVE-2025-1647
Type: DOM based Cross-site Scripting (XSS) using DOM Clobbering
Affected version: 3.4.1
Fixed in version: Bootstrap 3.4.x NES v3.4.7
Description: DOM-based Cross-site Scripting (XSS) via DOM clobbering occurs when an attacker manipulates the Document Object Model (DOM) to overwrite or "clobber" an existing DOM object, leading to the execution of malicious scripts. This technique takes advantage of the browser's handling of DOM elements and can occur entirely on the client side, bypassing traditional XSS protections on the server. In this case, there is a function in Bootstrap, sanitizeHtml, that can be forced to skip the sanitization if the createHTMLDocument method is clobbered.

Reproduction instructions

Note: This page currently uses the patched version of Bootstrap. To recreate the vulnerability and see the XSS attack in action, update the <head> tag includes to reference the original vulnerable Bootstrap 3.4.1 from a CDN: 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/css/bootstrap.min.css">
<script src="https://cdn.jsdelivr.net/npm/bootstrap@3.4.1/dist/js/bootstrap.min.js"></script>
File Modified: js/tooltip.js (also affects js/popover.js which inherits from tooltip)

Change Applied: Captured a safe reference to document.implementation.createHTMLDocument at module initialization time, before any DOM clobbering can occur, and modified the sanitizeHtml function to use this stored reference.

Location 1: Line 13-17 (after 'use strict', storing safe reference)
Code Added: 
// Store safe reference before any DOM clobbering can occur
var nativeCreateHTMLDocument = document.implementation && 
                                document.implementation.createHTMLDocument ? 
                                document.implementation.createHTMLDocument.bind(document.implementation) : 
                                null

Location 2: Line 112-119 (modified sanitizeHtml function)
Code Changed: 
// BEFORE (vulnerable):
if (!document.implementation || !document.implementation.createHTMLDocument) {
  return unsafeHtml
}
var createdDocument = document.implementation.createHTMLDocument('sanitization')

// AFTER (patched):
if (!nativeCreateHTMLDocument) {
  return ''  // Return empty string instead of unsafeHtml
}
var createdDocument = nativeCreateHTMLDocument('sanitization')
Rationale: By storing the reference to createHTMLDocument when the module loads (before user HTML is parsed), the code is immune to DOM clobbering attacks that try to override document.implementation. Additionally, returning an empty string instead of unsanitized HTML provides defense-in-depth.
Steps:
  1. Hover your mouse over the Template Tooltip button and observe the appearance of an alert and dismiss it to proceed. This alert represents the potential execution of malicious scripts. Hovering over the button again will not produce an alert because it is built once and cached so the onerror event triggers only the first time the template is rendered.
  2. Clicking on the Template Popover button will produce the same result as the Template Tooltip button.
  3. Hovering over the HTML Tooltip button behaves the same as the template buttons, but this alert will appear every time because HTML is re-rendered on every interaction causing the onerror event to fire each time.
  4. The same behavior as the HTML Tooltip button can be seen when clicking on either the HTML Title Popover or the HTML Data Popover buttons. To see the alert mutliple times for the popover buttons, they must be clicked twice - once to open the popover and show the alert and the second to close the popover. The alert must be dismissed each time it appears.
